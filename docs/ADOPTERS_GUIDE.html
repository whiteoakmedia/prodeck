ProDeck Adopter's Guide

ProDeck is a production-booth hub I built for my church: one app that ties ProPresenter, Planning Center, the audio consoles, NFC "tap" discs, crew phones, and the livestream into dashboards for the booth, phones, and kiosk screens.

This guide is honest about what you'd be adopting. Part I is the evaluation — what it does, what it assumes, and what's tuned to my room. Part II is the adoption — everything your tech person needs to stand it up in your environment without me on the phone.

Part I — Evaluate

01What you'd actually be adopting

Not a product. ProDeck is one church's custom tool: no vendor, no support contract, no license fee, and one maintainer (me), whose priority is my own Sunday. You'd be adopting a codebase — a well-documented one, but a codebase. The realistic ways to hold it:

  • You have (or can borrow) a developer: fork the repo, and it's genuinely yours. The stack is mainstream — Rust + React in a Tauri desktop shell, plus two small Cloudflare Workers — and a competent full-stack dev is productive in it within a week.
  • You don't: it still works — the core booth features run for years untouched (mine has no license checks and nothing that expires) — but bugs stay bugs and integrations drift as ProPresenter and Planning Center evolve. Go in with eyes open.

What it costs to run: a Mac in the booth, and if you want the phone/remote features, a Cloudflare account (free tier is enough) plus a domain (~$10/yr). That's the entire bill.

04What's specific to my church

The honest answer to "how personalized is this?" — in three tiers.

Tier 1 — just settings (change in the app, no code)

ProPresenter host, PCO credentials, all passwords and tokens, GA4 property/key, church coordinates, SPL calibration, MIDI ports and channels, Avantis host, audio channel routing, mic-position templates, checklists, call-time schedules, tap keyword→URL mappings, dashboard layouts. None of my values ship in the repo — a fresh install starts blank.

Tier 2 — four hardcoded spots (one find-and-replace each)

Tier 3 — shaped by my room (works for you, but review it)

  • Console + key-send: the desk mirror speaks Avantis; the key-send exists because my FOH runs Waves LV1 with per-key scenes. Different desk or workflow → skip or rewrite those modules.
  • Sunday shape: multi-service logic (auto-advance 8:00 → 9:30 → …), rehearsal-vs-service bucketing, and the readiness checklist reflect a multi-service Sunday with a volunteer crew. All configurable, but the shape is baked in.
  • Legacy migration shims: two tiny startup routines migrate data from the app's earlier internal name — harmless on a fresh install, and documented in src-tauri/src/lib.rs and src/main.tsx.

05Limitations, stated plainly

  • macOS only. The booth app is a Mac app. (Browsers/phones/kiosks connecting to it can be anything.)
  • Single maintainer, no test suite. I fix what breaks on my Sundays. Your bugs are your fork's bugs unless we agree otherwise.
  • Security model is passwords-over-HTTPS. Admin/member tiers, secrets never sent to browsers, admin actions gated server-side — sane, but it has never had a professional audit. If you expose it on your own domain, that's your risk to own.
  • Self-signed, unnotarized app. macOS will warn on first launch; mic/screen permissions are pinned to the signing certificate you create (Part II covers this).
  • Integrations track today's APIs — ProPresenter 7's network API, PCO API v2, GA4 Data API v1. Vendors move; someone has to move with them eventually.
  • The viewer count is web-player-only. GA4 can't see Facebook/YouTube simulcast viewers, and the widget says so on its face.

06Fit checklist & effort estimate

You're a good fit if…

  • ProPresenter 7 and Planning Center Services are already your Sunday backbone
  • You can dedicate one always-on Mac to the booth
  • Someone on or near your team can run terminal commands from a recipe (Part II is exactly that)
  • You want the tap discs, crew phones, or unified dashboards badly enough to own a codebase

Think twice if…

  • You need vendor support and SLAs — this has neither
  • Your booth is Windows-only
  • You mainly want the console features but don't run an Avantis

Part II — Adopt

07Phase 0 — try it on a spare Mac

Zero commitment: dev mode on any Apple Silicon Mac on your church network. No signing, no cloud, no install.

# prerequisites (one-time): Xcode command-line tools, Rust, Node 20+
xcode-select --install
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
brew install node   # or nodejs.org installer

# get the code (after I've added you to the repo)
git clone https://github.com/whiteoakmedia/prodeck.git
cd prodeck
bash scripts/setup.sh   # prereqs + config + dev mode, all guided

First run opens a setup wizard. Point it at ProPresenter (the ProPresenter machine's address (Find discovers it, or read the host and port from ProPresenter → Preferences → Network)) and paste a PCO Personal Access Token (create at api.planningcenteronline.com under any admin account). That's enough to evaluate everything tagged CORE in §2 — dashboards, show flow, slide grid, tracking, clear dock — plus SPL if you pick an audio input.

Evaluate against a real week

Load next Sunday's actual plan and leave a dashboard up through a midweek rehearsal. The value shows up in use, not in a demo click-through.

08Phase 1 — the booth install

Makes it permanent: a signed build that survives crashes and reboots unattended.

1 · Create your signing identity (once)

Keychain Access → Certificate Assistant → Create a Certificate: name it (e.g. YourChurch ProDeck), identity type Self-Signed Root, certificate type Code Signing. macOS pins microphone/screen permissions to this identity — keep using the same one forever, and never re-sign with hardened runtime (the install script refuses it for you).

2 · Create your updater keypair (once, optional)

npm run tauri signer generate -- -w ~/.prodeck/updater.key

Put the printed public key into src-tauri/tauri.conf.json → plugins.updater.pubkey, and point the endpoint at your own fork's releases — or delete the updater block entirely and install by hand each time. Guard the private key like a password: whoever holds it can ship code to your booth.

3 · Build, sign, install

TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.prodeck/updater.key)" npm run tauri build
codesign --force --deep --sign "YourChurch ProDeck" \
  src-tauri/target/release/bundle/macos/ProDeck.app
bash scripts/install-local.sh   # atomic swap into /Applications + watchdog handoff

Prefer a double-click installer? bash scripts/build-dmg.sh produces a drag-to-Applications ProDeck.dmg — hand it to anyone, no terminal needed to install (only to build). For an always-on booth, the script path below adds crash-relaunch and keep-alive that a plain drag-install does not.

Edit the identity name at the top of scripts/install-local.sh to match yours. The script expects the watchdog LaunchAgent from step 4 to exist.

4 · The three LaunchAgents

Ready-made templates live in deploy/launchagents/ — scripts/setup.sh --install installs and loads them for you. For reference:

PlistPurpose · ProgramArguments
com.prodeck.watchdog.plistRelaunch on crash · /Applications/ProDeck.app/Contents/MacOS/prodeck, RunAtLoad true, KeepAlive.SuccessfulExit false, ThrottleInterval 10
com.prodeck.caffeinate.plistNever sleep · /usr/bin/caffeinate -s, KeepAlive true
com.prodeck.cloudflared.plistPhase 2 only — the tunnel (§9)

Finish by enabling Browser Access in Settings (pick your admin + member passwords) and giving the booth Mac a DHCP reservation — do the ProPresenter Mac too, and skip the single most recurring failure I ever had.

09Phase 2 — your own cloud

Unlocks: crew phones anywhere, booth-off fallback, tap discs, kiosks beyond the LAN. Needs a Cloudflare account (free) and a domain on it.

  1. Domain onto Cloudflare. Buy or transfer any domain; add it as a zone.
  2. Make the four Tier-2 edits from §4 — your domain into PUBLIC_URL, EDGE_PUSH_URL, and crew-edge/wrangler.jsonc's route.
  3. Deploy the two workers. In crew-edge/ and taplink-edge/: npx wrangler login then npx wrangler deploy. Set each worker's secrets with npx wrangler secret put <NAME> — the names are listed at the top of each worker's src/index.ts (admin token, PCO pair for the edge fallback, tap tokens).
  4. Tunnel the booth. brew install cloudflared, then cloudflared tunnel login, cloudflared tunnel create booth, and a config at ~/.cloudflared/config.yml routing your hostname → http://localhost:8088. Add the DNS route (cloudflared tunnel route dns booth yourdomain.com) and wrap it in the com.prodeck.cloudflared LaunchAgent. Tunnel only the gateway port — never video.
  5. Wire the booth to the edge: Settings → paste the edge admin token you chose in step 3. From then on install-local.sh keeps the edge's fallback copy in sync on every install.
  6. Verify booth-off mode: quit ProDeck (watchdog off for a minute) and load your domain from a phone on cellular — you should get the read-only plan + chat. Restart, and it's live again.

11Ongoing care & staying current

  • Fork, don't track. Fork the repo and make your Tier-2 edits on your fork. Pull from mine when something looks worth taking — my commits are messaged plainly. Nothing forces us to stay in sync.
  • Back up two things off the booth Mac: the data folder ~/Library/Application Support/ProDeck/ (all settings, layouts, reports, crew accounts — settings.json inside it holds every secret) and your updater key. Your fork covers the code.
  • Write your own succession page. I keep a companion "run and maintain this if I'm gone" handbook for my team; do the same on day one, while the setup is fresh. Ask me for my template.
  • When something breaks Sunday morning: the app self-restarts on crash; ProPresenter reconnects are the most common fix; and nothing in ProDeck can take down ProPresenter, your consoles, or your stream — it fails soft, by design.

Where I land on it

If the tap discs, crew phones, or one-glance dashboards solve a real problem for your team, the adoption cost is a few honest days and a codebase to own. If they don't, skip it without guilt — everything underneath (Pro, PCO, your consoles, your stream) already works without it. Questions to zach@whiteoakmedia.io.
